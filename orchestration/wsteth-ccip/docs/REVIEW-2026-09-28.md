## FPF basis and decision rule

**A.10 §6 items 1, 3, 6, 8, 9** govern the claim-to-source account: identify the
failure condition, inspect the actual implementation, preserve historical editions,
and distinguish a provenance record from executed work. A finding is accepted for
repair when the current code contains its reachable failure and the repair has a
specific behavioral check. Deliberate behavior and historical facts are qualified
before choosing an improvement.

**B.3 CC-B3-1/2/6/8/12** govern the assurance conclusion here: these changes repair
the named orchestration defects within the tested conditions. The evidence and
limits below belong to that claim. A prior green fork run neither disproves a
fresh-clone failure nor establishes correctness after an implementation change.
No numerical confidence average or universal “safe to deploy” score is inferred.
Reopen a conclusion if its checkout layout, CLI, dependency pin, Foundry behavior,
or execution path changes.
