The September deployment uses UUPS POM proxies and the updated upstream API. There is no proposal mode, guardian role, veto, or approve function on this POM.

Authority Holder on each POM Effect
DEFAULT_ADMIN_ROLE L1 Agent / L2 OpExec Direct calls, role administration, UUPS upgrades, pool/selector/delay settings; admin bypass for pause and restart levers
PROPOSER_ROLE Chainlink MCMS testnet EOA propose and cancel; admin has no implicit proposer bypass
PROPOSAL_QUEUE_HALT_ROLE Emergency and MCMS testnet EOAs haltProposalQueue(); increments epoch and invalidates pending proposals
CROSS_CHAIN_TRANSFERS_PAUSE_ROLE Emergency and MCMS testnet EOAs pauseCrossChainTransfers() and pauseRemoteLanes(...)
PROPOSAL_QUEUE_RESTART_ROLE Empty restartProposalQueue() is admin-only under this configuration
CROSS_CHAIN_TRANSFERS_UNPAUSE_ROLE Empty Direct unpauseCrossChainTransfers() / unpauseRemoteLanes(...) are admin-only
EXECUTOR_ROLE Empty Anyone can execute a ready proposal

The deployer holds no POM role. The named Emergency and MCMS holders are disposable EOAs, not production multisigs. Deployer authority outside the POM includes the OpExec guardian and verifier allowlist administrator; see the state checks for the exact scope.

Queue and selector rules

Proposals have a 3-day minimum delay and expire 30 days after creation. The six selectors in custom_delay_selectors have a 14-day minimum. Governance may change these settings directly. A ready proposal is permissionlessly executable while the queue runs. There is no veto step: Emergency can halt the whole queue, invalidating its current epoch. Restarting does not restore invalidated proposals.

setSelectorBlocked(bytes4,bool) controls admission; isSelectorBlocked(bytes4) reads it. Blocking a selector does not invalidate already queued proposals. The filter is target-blind.

  • Both chains block transferOwnership(address) (0xf2fde38b) and upgradeToAndCall(address,bytes) (0x4f1ef286) from proposals.
  • L1 additionally blocks unpauseCrossChainTransfers() (0xa6cc6ef9).
  • L2 allows a proposal targeting the hooks' unpauseCrossChainTransfers() after the global delay.

A proposal can already be ready when a pause occurs: halt the queue as well when pending restart proposals must be invalidated.

Queue halt, global transfer pause and per-lane pause are separate controls. Queue halt does not pause transfers or disable admin direct calls. Unpausing global transfers leaves lane pauses intact.
